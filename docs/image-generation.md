# 网页生图

生图入口是 `/images`，聊天侧栏与个人导航均可进入。界面改编自
[AI Elements 的 Image 组件及官方示例](<https://github.com/vercel/ai-elements/blob/ca8be600bfd01b3131f9bf6134b51602a71f4374/apps/docs/content/components/(utilities)/image.mdx>)，
生成操作使用项目现有的文字按钮。来源、固定版本和 Apache-2.0 许可见
`THIRD_PARTY_NOTICES.md`。

## 支持范围

首版通过管理员配置的渠道调用 OpenAI 兼容 `POST /v1/images/generations`。
每次生成一张，支持文本提示词、配置允许的尺寸、固定画质、预览、原图下载与
分页历史。支持 PNG、JPEG、WebP 的 `b64_json` 返回值。
不额外按图片字节数、HTTP 分块数或提示词字符数拒绝供应商结果/用户输入；
入站请求沿用网关统一的请求体读取机制，模型参数能力由供应商决定。
这不代表无限容量：Worker 的内存和执行时限仍适用，base64 响应目前在内存解码。
GPT Image 通常使用默认返回参数；DALL·E 可显式配置 `b64_json`。
不下载供应商返回的任意 URL。不包含参考图上传、局部重绘、多张批量和视频。

接口位于 `/api/v1/images`，使用浏览器登录身份和 CSRF 校验。此批未开放面向
API Key 的 `/v1/images/generations` 代理，也未改动 Chat/Responses/Messages 的
协议转换矩阵。

## 上线配置

1. 应用 `0031_image_generation.sql` 与 `0032_image_billing.sql`。后者迁移现有账本，
   保留旧记录与六个会计触发器，增加独立的图片消费类型；迁移本身不改变余额。
2. 创建私有 R2 桶 `cheapai-generated-images`，并将 Worker 的 `IMAGE_ASSETS` 绑定
   指向它。预览环境使用单独的 `cheapai-generated-images-preview`，不能共用生产桶。
   `wrangler.jsonc` 已声明这些绑定；本地模拟器使用本地桶。代码变更不代表已创建
   远端桶或已执行生产迁移。
3. 在已有「渠道」中配置供应商 Base URL 和密钥，将渠道加入允许使用的访问组。
4. 在 `/admin/image-models` 添加显示名称、渠道、供应商模型、单张售价、尺寸和
   画质参数。默认不会预置免费模型或供应商密钥。
5. 授权用户相应访问组，再使用该用户验证生成、下载和费用记录。

R2 桶保持私有；图片通过核对所有者的同源下载路由读取。历史中只保存对象路径和
元数据。禁用渠道或模型会阻止新生成，已生成的个人图片仍可读取。

## 价格与请求归属

售价由管理员按张配置，所有允许尺寸使用同一售价，再乘访问组倍率。报价使用
整数 USD 单位计算并保存不可变快照，执行期间改价不会改变已接受请求的价格。
成功保存图片后才写入 `image_generation` 账单。费用页面包含图片消费及记录链接，
原有账本触发器原子更新余额。与现有文本消费一样，生成前检查余额，实际已发生
的成功消费仍会记账；并发请求可能使余额短暂为负。

每次点击生成创建一个 operationId。同一账号对该 ID 的重试只读取已注册记录，
参数不一致返回冲突；不会自动重新调用供应商。并发与频率限制复用现有用户和
渠道 Gate。供应商超时或连接中断时，本次交付明确失败且不扣费，操作 ID 和原描述保留供查询。
确认与刷新不发起第二次生成。再次生成是新的明确用户操作。

提交接口在 D1 保存不可变执行参数，并持久化 Durable Object alarm 后返回 HTTP 202。
`generating` 包括等待执行和执行中；GET 单条记录与历史可查询进度，前端继续轮询。
关闭页面、断网或退出登录不会取消已接受任务。alarm 独立于提交请求执行，单次上游
调用最多 180 秒。使用平台已有的 Durable Objects 能力，不引入 Queues 或外部服务。

D1 同时作为待调度记录：每五分钟的维护任务最多补调度 20 条，修复写入 D1 后
唤醒失败的提交；原 operationId 的确认也可补调度。等待超过十分钟仍未执行会失败，
不会收费。执行时获取用户/渠道 Gate 配额，容量不足或渠道版本变化时失败且不扣费。
执行前写入持久化开始标记；alarm 重投或执行进程中断后，不再次调用供应商，任务
明确以交付失败结束且不扣费。这个保守选择可能放弃尚未实际发送的请求，避免重复上游成本。

图片写入私有 R2 并记录成功后才结算；失败任务不计费。结算失败保留图片和
pending 状态，由 alarm、五分钟维护和所有者查询重试同一笔账单，唯一约束保证不重复
扣费。旧请求没有执行快照，迁移后不会被误当成新后台任务再次执行。

上线还需要应用 `0035_image_background_jobs.sql`、`0036_image_delivery_finality.sql` 并部署 `IMAGE_JOBS` 绑定与
`v2-image-jobs` SQLite Durable Object migration（本地、预览、生产配置已声明）。
本变更不执行远端迁移或部署；平台任务执行与存储仍按 Cloudflare 套餐计费。
机制参考 [Cloudflare alarms 文档](https://developers.cloudflare.com/durable-objects/api/alarms/)。

## 交付终态与供应商限制

图片任务只有 `generating`、`completed`、`failed` 三种状态。`failed` 表示本系统
未能交付图片，并不声称供应商没有执行。迁移将旧 `unknown` 记录转为交付失败；
数据库触发器禁止重新写入旧状态，并禁止失败任务转成功、恢复执行或扣费。
迟到的图片不会使已失败任务重新计费，新写入的迟到对象会删除。

当前渠道只有同步 POST 接口，没有供应商任务 ID 查询、结果对账或幂等键能力。
因此无法同时保证断线后必得图片和上游绝不重复计费。当前采取不自动重发、用户
不扣费、平台承担可能已发生的上游费用的处置方式。原操作查询只返回终态；用户
明确重新生成才创建新操作，按新报价执行。若要自动恢复供应商结果，需要供应商
提供可持久化任务 ID、查询 API 或有明确保证的幂等请求能力，再做渠道适配。

结算 `pending` 是已确认图片存在、金额确定的待记账状态，alarm 和维护任务继续
重试同一笔账单；不能为了消除等待而伪造结算成功。数据库或网络整体不可用时，
无法保证在固定时间内完成查询或持久化收敛，恢复后由既有维护路径继续处理。

## 交互验收

- 点击后立即显示原描述与生成占位，输入区允许编辑下一条描述。
- Enter 换行，Ctrl/⌘+Enter 生成；中文输入法选词不触发生成。
- 生成期间锁定重复提交，失败保留描述，余额不足允许恢复和修改描述。
- 网络中断尚未确认提交时保留原操作，提供「确认生成结果」；不静默重试新的操作。
- 使用明确的「生成图片」文字按钮，并在提交前展示当前价格。
- 复用恢复描述、模型、访问组和尺寸，不直接发起生成；原模型不可用时要求重新选择。
- 复用覆盖草稿后可以撤销；图片显示生成时间，支持复制描述、查看关联费用。
- 预览支持 Escape 与焦点返回；下载走同源鉴权地址。
- 模型不可用、图片读取失败和历史读取失败均有可见反馈与恢复操作。

测试分别覆盖原生 D1/R2/Gate 与模拟上游的服务端集成、组件状态与桌面/窄屏浏览器。
真实供应商联调需要已配置的渠道及密钥；模拟用例不会消耗供应商额度。

功能取舍及与 Sub2API 的差距见 [功能对照](sub2api-functional-review.md)。
