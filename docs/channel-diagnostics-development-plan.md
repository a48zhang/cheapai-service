# cheapai 渠道诊断开发计划

日期：2026-10-11。设计依据：[PRD v2](channel-diagnostics-prd.md)。代码调查基线：main 的 `c1f2113`；执行时以实际工作分支为准，已有同等实现应接续使用。

本计划供后续 subagents 执行。本次按该计划派发实现；执行分支基线已同步到 main 的 `acad0e2`。

## 一、交付目标

继续使用现有 ChannelDiagnostics / Sheet，桌面宽度 544px，手机沿用当前 Sheet 适配。内部仅「结果 / 请求 / 响应」三个 Tabs。管理员能看到本次实际请求、具体错误、脱敏响应正文和失败阶段；上游错误不再只有 HTTP code。

功能范围包括真实请求快照、有界响应采集、具体协议错误、受控的部分诊断错误详情、复制/导出及明确修复入口。沿用现有诊断 POST、权限、CSRF、版本检查、审计和调用限额。

本次不新增诊断页面/路由、数据库迁移、D1/KV/R2 诊断历史、自动重试、定时探测、任意请求编辑器或通用诊断框架。当前生产已完成 0026 迁移，本功能不再执行迁移。

## 二、执行规则

1. 每个实现任务限定到表中的文件，最多 3 个。发现必须扩大范围时，协调者先拆出后续任务，不能由 subagent 顺手重构其他模块。
2. 每个任务说明依赖、具体工作和最终代码状态。依赖表示上游代码/契约已经交付，**不表示必须先跑测试或验证**。
3. C/B/F/I 是实现任务，不附带「先跑测试」「完成后跑测试」「验证通过后交付」等前后条件。
4. T 是编写必要测试的任务，只写测试，不执行。V 是独立的集中执行任务，全部安排在完整诊断功能已组装之后。
5. 未完成实现期间不反复执行 typecheck、build、浏览器脚本和整仓测试。集中执行有实际失败时，只重跑相关检查；只有共享依赖变化或新的影响范围才扩大范围。
6. 同一文件同时只归一个任务所有。任务可引用其他已交付模块，不能替其他 agent 修改其文件。协调者处理合并和最终连接。
7. 复用现有 Sheet、Tabs、Button、StatusBadge 和 API 客户端。没有明确复用价值的代码留在诊断 feature，不抽成全局组件。
8. 单个文件出现采集、格式化、状态编排和 UI 多种职责时按本计划拆开。文件长度不作为机械门槛，不为了减行数新增只有一层转发的包装。
9. 任务交付说明只报告修改文件、公开接口、已实现行为和剩余问题；不能把未执行的检查写成通过。

## 三、先固定的接口与行为

这些决定由 C-01 落地，后续任务不能各自改名或另起结构。

### 3.1 结果与错误

- 保留原 `ChannelProbeResult` 字段和六种 outcome；完整结果新增 `evidence`。
- `evidence` 的结构、execution、failure.source/phase、request/response 和 phases 以 PRD 为准。
- `evidence` 在客户端解码中可缺省，以兼容旧 Worker。缺省时只显示已知 outcome/status，明确缺少详细证据，不补造正文。
- 管理 API 200 与上游 HTTP 状态分开。上游 401/429/5xx 返回诊断结果，不触发浏览器会话退出。
- 管理 401/403 保持现有错误边界，不返回诊断详情。
- 已认证管理员的 409/5xx 可返回 `error.details.diagnostic`，其值为同一个 `ProbeEvidence`；失败时已经生成的 diagnosticId 作为受控详情中的可选字段。不能把 exception/cause/stack 当作 details 序列化。
- 接口保留原管理错误状态，部分诊断和 API 错误可以同时存在。审计失败发生在上游调用之后时保留已采集响应，并标记 audit 阶段失败。

### 3.2 采集与限额

- 探测请求固定，输出上限取 `min(16, 模型上限, 映射上限)`，非流式，上游传输总时限不超过 10 秒（包含跳转与正文读取）；D1 配置与审计耗时单独记录。
- 响应采集最多 32 KiB；限额附近只保留必要探测数据，不额外读取整段正文、不 clone 第二条无界流。采集、解析复用同一份有界字节。
- 超限与完整非法 JSON 是不同状态；读取中断保留已取得的头、状态、正文片段。
- 请求快照来源于 transport 实际准备/尝试发送的 RequestInit；发生跳转时记录各跳和最终目标。诊断正文记录本次真实上游模型名。
- transport 观测可选且按单次调用传入。普通网关不传观测器时行为一致；回调异常不能增加 fetch、打断主请求或改变重试行为。
- HTTP 跳转是同一次诊断的传输过程，不等于自动重试。无跳转的测试才断言 fetch 一次；有跳转时断言各跳次数和方法正确。
- 返回、复制和导出都使用服务端脱敏版本；保留可排错的 provider code/message。头部白名单、敏感字段、已知 Key、敏感 URL 参数和截断凭据区域均受同一清除策略约束。
- 调用前校验必须发生在实际 fetch 前。时间数据只来自可观测阶段，不伪造 DNS/TCP/TLS 耗时。

### 3.3 预览与前端状态

- 未运行时展示映射、Base URL、固定提示词和请求模板，明确是预览。客户端不知道完整模型/映射输出上限，因此只标示「最多 16 tokens」；精确的实际 URL、头、输出上限以运行后证据为准。
- 运行中锁定选择器与运行按钮；切 Tabs、复制、下载、展开详情不产生请求。
- 选项变化清除旧结果；切换渠道、关闭/卸载或用户身份变化后丢弃当前结果。迟到响应不能进入新渠道或新用户面板。
- 断线/abort 显示结果未确认。关闭读取不是停止上游，不提供保证停止执行的按钮。
- 单一运行按钮发起一次诊断，底部保留费用说明；撤掉当前重复的大费用卡和二次确认弹窗。
- 模型与协议来自配置好的映射选项，不能把 Demo 的独立协议选择器理解成随意更改生产请求协议。

## 五、并行安排

共 **36 个任务**：24 个实现/连接任务、7 个测试编写任务、3 个集中验证任务、2 个 PR 交付任务。实现任务均为 1–3 文件。

每个批次是调度窗口，不要求前一批所有任务结束才开始下一批；具体按依赖就绪补位。按当前 7 个总并发槽，协调者占 1 个，最多 6 个执行 agent 同时工作。执行时遵守同文件 owner 串行边界。
