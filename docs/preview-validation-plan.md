## 执行约束

1. 使用最多 6 个 `gpt-6-luna`、`max` 推理代理并发，协调者保留第 7 个位置。准备工作完成后同时派发六条完整模块链路。
2. 每个代理拥有独立浏览器 context、会话文件、数据清单和报告文件。凭据与 storageState 放在仓库外的受限目录，文件权限 0600；报告、截图、日志和 PR 不包含密码、Cookie、CSRF token、密钥明文或邀请码明文。
3. 协调者负责 Wrangler 配置、账号初始化、额度准备和跨模块数据交接。代理只修改分配给自己的测试资源；涉及其他 lane 的账号、访问组或映射，由协调者安排串行窗口。
4. 不修改已有用户密码/权限、默认组、全局注册策略、已有渠道密钥或 keyring；不清空共享 D1/KV/Gate，不执行部署、迁移或恢复数据库。
5. 每个验证任务覆盖一个完整链路。实现修复任务不要求执行测试，不把测试通过作为其前后条件。模块修复完成后集中复验该模块，最后执行一次跨模块链路。
6. 不直接将现有本地 E2E 套件指向预发：其中包含本地模拟服务、`/__test__` 接口、全局策略修改和忽略 TLS 错误。新预发浏览器会话保留 TLS 验证。
7. 真实上游调用总计最多 12 次，单次最多 128 个输出 token，总预算上限 $0.10。先按已配置模型价格核算；额度不足或没有满足预算的预发模型时记录阻塞，不自动增加额度或接入新供应商。
8. 只采集本轮资源的详情证据；管理列表中的其他用户与请求信息不进入公开附件。品牌检查面向产品页面，内部 Cookie、资源名与兼容协议标识不属于改名范围。

### 当前实例的账号准备替代路径

本地 Wrangler 未认证，但已成功部署的 CI 持有原有 Cloudflare 凭据。本轮通过临时 CI 步骤完成 P-02/P-04：沿用成功部署生成的配置，严格校验固定 PR、Account、Worker、D1/KV，再用 Wrangler 新增本轮管理员。CI 生成随机密码，只把 AES-GCM 加密、RSA-OAEP 包装密钥的账号 envelope 上传为一天有效的 artifact；RSA 私钥仅留在当前工作区受限目录，Cloudflare Token 留在 CI。已有邮箱若不是本轮 ID 则停止；同一本轮账号若已存在则不重置密码。协调者取得并核验 envelope 后通过产品 API 完成 P-05/P-06。

临时准备写集为 `scripts/seed-preview-qa.ts`、公开 recipient 元数据 `scripts/preview-qa-fixture.json` 和 `.github/workflows/preview.yml`，共三个文件。账号交付已成功，协调者已移除这三个文件中的临时步骤/产物，保留现有正常预发流水线；随最终验证报告一并提交。

## 每个代理的交付格式

- 地址、部署 SHA、执行时间、角色与案例 ID；不包含凭据。
- 每条链路记录 `通过 / 失败 / 阻塞 / 未执行`，说明实际覆盖的步骤。
- 失败项提供最短复现、实际/预期、相关 request/resource ID、脱敏截图或必要响应字段。
- 列出定向注入的故障、自己创建/修改的资源及已消耗上游调用数。
- 缺失渠道、邮件关闭、当前策略不允许注册等作为明确限制；不能以“页面能打开”替代业务验证，也不能将未执行项写成通过。

本计划的第一轮并行验证预计 20–40 分钟，准备约 10–15 分钟，汇总与最终链路约 10–20 分钟；实际耗时取决于 Wrangler 会话权限、预发渠道以及发现的缺陷。修复与 CI 等待另计。
