# 聊天首页与分组倍率实施方案

日期：2026-09-12。状态：本地已实现并通过验收，待 Cloudflare 授权恢复后发布。实际交付见 web-chat-delivery.md。

## 1. 目标与边界

用户打开首页，登录后选择自己有权限使用的分组和模型，即可进行多轮文字聊天；无需创建 API Key。网页聊天与外部 API 使用同一个账户余额、模型目录、分组渠道和结算系统。

本期范围：

- 聊天首页、历史会话、跨设备读取与继续聊天。
- 模型/分组选择、流式回答、Markdown、代码块与复制。
- 停止生成、最后一条回答的重新生成及版本切换。
- 会话重命名与删除、失败与余额不足时保留输入内容。
- 每用户一个无密钥凭据的内部虚拟 Key。
- 模型基础价乘分组倍率，网页和 API 一致计费。

本期不包含附件、联网搜索、工具执行、知识库、分享链接、复杂分支树、自动生成标题、套餐订阅或新的支付接入。账户入口继续使用已有余额、账单与兑换能力。

不恢复已经删除的默认输出配置，不新增后台输出补值策略。虚拟 Key、聊天和 API 继续共用既有用户/渠道并发规则，不增加独立的聊天 RPM 配置。

## 2. 产品结构

| 路径/入口 | 内容 |
| --- | --- |
| `/` | 新对话首页；未登录可输入草稿，发送时登录 |
| `/chat/:id` | 当前用户的历史对话 |
| 账号菜单 → 余额与账单 | 余额、消费记录与兑换入口 |
| 账号菜单 → API 控制台 | 现有 Key、API 请求记录和开发者功能 |
| `/admin/*` | 保留现有管理后台；在分组设置中增加倍率 |

原仪表盘保留在控制台入口。已有控制台链接尽量保持可访问，不借此次改动重排所有管理路由。

桌面布局：左侧会话列表，顶部模型选择，中央消息，底部输入框。手机使用折叠侧栏。空白页只保留简短提问引导，不放协议宣传、功能卡片或计费小字。余额放账号区；单次消费和 Token 明细放展开详情/账单。

模型选择器按分组分区，显示组名和倍率，再显示该组下的模型。同名模型在两个分组里是两个可选项，但使用同一个全局模型 ID。会话记住最后选择；每条助手消息记录实际使用的组和模型，切换不会重写旧消息。

## 3. 复用关系

```text
网页 Cookie 会话 + CSRF → 服务端取得虚拟 Key → 本次选择并授权的分组
外部 Bearer API Key   → 普通 Key           → Key 绑定的分组
                                      ↓
                现有准入、渠道选择、协议转换、JSON/SSE 执行
                                      ↓
                    上游真实用量 + 基础价/倍率快照
                                      ↓
                            现有账务与余额
```

聊天接口在服务端直接复用网关执行函数，不绕回 HTTP `/v1/*`，不伪造 Bearer 凭据。网页本身的会话和消息存储放在聊天模块，不混入外部 API 的协议转换包。

Cloudflare Workers、D1、现有 Gate DO 和 KV 继续使用。不为本期新增聊天 DO、消息队列或另一套计费服务。FC/境外中转属于独立网络工作，本期不以它为前置条件，也不把聊天 Cookie 转发到尚未验证的中转入口。

## 4. 虚拟 Key

扩展现有 `api_keys` 表，而不是给用户生成隐藏的可调用密钥。

| 属性 | 普通 Key | 虚拟 Key |
| --- | --- | --- |
| `kind` | `api` | `web_chat` |
| `key_hash`、展示前缀 | 保持现有规则 | NULL |
| `group_id` | 固定授权分组 | NULL |
| 外部 Bearer 查询 | 可匹配 | 明确排除 |
| 普通 Key 管理与数量统计 | 包含 | 排除 |
| 请求日志中的展示 | Key 名称 | 网页聊天 |

首次聊天时幂等创建，数据库保证每用户至多一个 `web_chat` Key。该身份不因重新登录或新建会话而变化，浏览器不能传入 Key ID 来选择内部身份。所有普通 Key 的读取、编辑、撤销和按创建操作恢复结果的接口都需要排除虚拟 Key，不能只隐藏前端列表。

虚拟 Key 不绑定会话分组。两个会话同时使用不同分组时，分别带入自己的请求分组，不修改共享虚拟 Key。

现有约束需要真实迁移：`key_hash` 和前缀当前非空，0017 的触发器会给 NULL 分组自动补默认组。迁移必须调整这些约束及触发器，普通 Key 的既有约束继续成立，保留 `requests.api_key_id` 外键与历史记录。不能使用假哈希或假前缀充当可鉴权数据。

## 5. 请求身份和分组授权

两种入口分别完成鉴权，再构造仅供服务端使用的调用上下文：用户、Key ID、Key 类型、本次分组、相关版本。外部请求体不能切换身份类型。

- 普通 API：当前分组必须等于普通 Key 的分组，保留已有模型限制。
- 网页聊天：当前分组来自用户选择，服务端检查 `user_group_access`、用户/组状态及组内可用模型。
- 两种入口都只从该分组的可用渠道中选择，不跨分组自动回退。
- 聊天每次发送都重新检查权限，会话记住的选择不是永久授权。

需要同时调整身份查询、余额准入和最终请求注册 SQL。尤其不能只在聊天路由通过一次检查，随后仍让底层按 `k.group_id` 读取虚拟 Key 的空分组；也不能为了兼容虚拟 Key，放宽普通 Key 的组校验。

## 6. 分组倍率和账务

全局模型继续保存输入、输出及缓存等基础价格。分组新增 `billing_multiplier`，默认字符串 `"1"`，允许非负精确十进制，统一作用于全部现有 Token 计费项；0 表示管理员明确设置免费，缺失或错误值不解释为免费。

```text
费用 = Σ(每类实际 Token × 该类模型基础价) × 分组倍率 / 1,000,000
```

复用整数金额运算，以十进制字符串解析倍率，不使用 JS 浮点乘法。保留未舍入的计费分子，乘倍率后按现有规则统一舍入一次，不能先算整单位费用再打折。

新请求保存组 ID、组版本、倍率及模型基础价/价格版本快照。请求注册时核对版本，结算与恢复重试只使用保存的快照；中途调价不改变在途请求费用。倍率更新沿用组版本和审计，不另建价格版本系统。

旧价格快照按倍率 1 读取，保持旧指纹/幂等校验兼容，不能在读取时重写历史账务。新请求明确保存所用分组；旧记录无法确认历史分组时保持未知，不拿 Key 当前分组猜测回填。

网页与 API 共用余额准入、扣费、允许透支及用量未知时的现有处理。重新生成属于新的模型请求，可再次计费；重复提交同一次发送不能产生第二次调用或账单。

## 7. 会话数据

新增两张业务表，不另建消息版本表：

| 表 | 核心字段与约束 |
| --- | --- |
| `chat_conversations` | ID、用户、标题、当前分组/模型、更新时间、用于防止跨标签页覆盖的版本 |
| `chat_messages` | ID、会话、轮次、角色、文本、生成状态、版本序号/是否选中、操作 ID、关联请求 ID、实际分组/模型、时间 |

消息状态为生成中、完成、已停止、失败。助手回答的不同版本作为独立消息行保存，后续上下文只选每轮当前版本；一个请求至多关联一条助手生成记录。

服务器从当前用户的会话记录组装上下文，只接受客户端本次新增输入和已授权的模型选择。完整聊天内容不写进通用请求日志，日志只保留必要关联信息。

一个会话只有一个正在生成的回答，使用 D1 条件写入/唯一约束避免跨标签页冲突，不引入新的调度服务。其他会话独立运行，仍受现有用户并发配置管理。

标题取首条用户消息片段，可手动修改。重新生成限最后一轮，旧回答在新版本产生前保留；重新生成失败不能抹掉旧答案。切换旧版本时检查该轮仍是最后一轮，避免暗中生成分支树。

删除会话移除聊天内容，但保留扣费和请求审计记录。正在生成的会话先停止后删除；写入条件防止迟到的保存重新创建已删除内容。

## 8. 发送、流式与停止

1. 验证登录、CSRF、会话归属及本次组/模型权限。
2. 按唯一操作 ID 接受一次发送，保存用户消息及待生成的助手记录。
3. 取得虚拟 Key，复用现有准入与请求注册；将助手消息关联到唯一请求 ID。
4. 执行上游请求，沿现有适配器输出聊天文本，逐段推送给浏览器。
5. 内存累计回答并做低频阶段保存，不逐 Token 写 D1；结束时保存最终内容和状态。
6. 复用现有终结/结算链路，分别表达“回答状态”和“账务状态”，用量未知不伪装成已结清。

重复操作返回已有关联结果/当前状态，不再次调用模型；第一版不做 SSE 断点续传。刷新页面读取保存的内容和请求状态，不因为看到“生成中”就重新发起模型请求。

停止按钮取消当前流式连接，复用网关的断开取消路径终止回源并保存已生成部分。不额外建立跨实例停止控制服务。进程异常时由关联请求的已有恢复结果修正遗留状态；阶段保存之间尚未持久化的文本可能丢失，一期不承诺零丢失的后台生成。

## 9. 接口边界

接口统一放在 `/api/v1/chat` 下，所有读写均校验当前用户归属；写接口沿用 CSRF。

| 接口职责 | 行为 |
| --- | --- |
| 可用模型 | 返回授权分组、倍率及各组可用模型，不泄露上游渠道凭据 |
| 会话列表与内容 | 分页读取当前用户会话及消息版本 |
| 创建、重命名、删除 | 管理会话与记住的选择 |
| 发送消息 | 操作 ID、新输入、分组/模型，返回流式结果及消息/请求关联 |
| 重新生成 | 对最后一轮建立新的回答版本与收费请求 |
| 选择回答版本 | 更新最后一轮的当前版本 |

停止使用发送连接的取消行为，不再单独增加一个缺乏跨实例执行机制的 stop 接口。

## 10. 实施顺序与交付关口

先做底层，再做可运行的最小文字对话，最后补历史交互与发布。以下是工作包；执行时将每个工作包拆成至多修改 2–3 个文件的子任务，数据库、服务端、前端和测试分别落地，不能把整个工作包当作一个小任务。

| 工作包 | 内容 | 依赖 | 完成标准 |
| --- | --- | --- | --- |
| A1 | 分组倍率迁移、模型与校验 | 现有分组模块 | 老分组默认 1，倍率精确保存 |
| A2 | 价格快照、计算、恢复兼容 | A1 | API 按倍率计费，旧请求金额不变 |
| A3 | 分组管理 UI、倍率审计与展示 | A1–A2 | 管理员可改倍率，版本检查生效 |
| B1 | Key 类型、空凭据、唯一虚拟 Key 迁移 | 现有 Key 模块 | 保留普通 Key 和请求外键，首次创建幂等 |
| B2 | 普通 Key 鉴权与管理隔离 | B1 | 虚拟 Key 不能外部调用、列出或修改 |
| B3 | 聊天会话鉴权与请求级分组 | B2、A2 | 相同虚拟 Key 的不同分组请求互不影响 |
| B4 | 最终请求注册、快照、日志来源 | B3 | 网页与 API 共用执行和账务，组版本原子校验 |
| C1 | 会话/消息迁移与归属 CRUD | B1 | 只能读取和操作自己的会话 |
| C2 | 发送操作幂等、请求关联、上下文组装 | C1、B4 | 一次发送只建立一个收费请求 |
| C3 | 流式累计、阶段保存、结束/取消保存 | C2 | 回答逐段显示，取消和失败保留已有内容 |
| C4 | 遗留生成状态与已有请求恢复衔接 | C3 | 异常后不会永久显示生成中或重复生成 |
| D1 | 聊天布局、模型选择、登录草稿 | A3、B3 | 首页可选授权组和模型，登录不丢草稿 |
| D2 | 输入发送、流式展示、停止与错误状态 | C3、D1 | 能完成一轮真实执行路径的模拟对话 |
| D3 | 历史列表、继续聊天、改名和删除 | C1、D2 | 刷新/重新登录后可继续使用 |
| D4 | 最后一轮重新生成与版本切换 | C2、C3、D3 | 旧答案保留，新请求独立计费 |
| D5 | Markdown、代码复制、移动端、控制台入口 | D2–D4 | 页面可日常使用，没有新增说明文字堆积 |
| E1 | 集成与迁移回归 | A–D | 下方关键验收全部通过 |
| E2 | 测试站发布、只读页面复核 | E1、有效 CF 授权 | 迁移与 Worker 发布成功，页面和日志一致 |

关键路径：`A1 → A2 → B3 → B4 → C2 → C3 → D2 → D3 → D4 → E1 → E2`。
可独立准备：B1/B2、C1 和聊天静态布局；不提前把未完成的新入口替换到线上首页。

每个阶段都保留普通 API 的回归检查。新计费和虚拟身份先稳定，再让首页调用，减少同一故障同时涉及 UI、会话和账务的排查成本。

## 11. 验收标准

- 普通 Key 的创建、撤销、分组授权及三协议请求保持正常。
- 虚拟 Key 无可调用凭据；猜到 ID、伪造请求类型或走普通 Key 管理接口均不能使用它。
- 两个网页会话同时选择不同分组，不串渠道、不串倍率；跨用户会话操作被拒绝。
- 同模型在 1× 与 0.2× 分组、包含缓存用量时金额正确；倍率更改不影响在途请求。
- 极小金额只在最终舍入，旧快照与恢复幂等保持兼容。
- 双击发送、网络重复提交不会重复调用/扣费；主动重新生成是新请求。
- JSON/流式、停止、上游失败、用量缺失及余额不足时消息与账务状态符合既有规则。
- 刷新、重新登录和移动端可读取会话；生成失败不丢用户草稿或旧回答。
- 首页没有协议实现说明、默认输出设置或密钥创建前置步骤。

默认使用本地模拟上游完成集成，不自动增加真实模型消费或发送邮件。真实上游验收沿用此前“暂不急着验收”的安排，需要已有可用配置时再单独执行。

## 12. 当前基线与待发布事项

聊天首页、分组倍率、虚拟 Key、会话历史和统一执行/计费链路已实现。现有全局模型目录保留 23 个预设型号，普通 API 控制台仍可使用。

待发布迁移依次为 0019（移除默认输出）、0020（倍率）、0021（虚拟 Key）、0022（会话/消息）、0023（请求来源/组）。0001–0018 未改写。本次发布预检通过，但 Cloudflare CLI 确认 OAuth 已过期且无法刷新，未执行远程迁移或更新线上 Worker。
