# 管理员上手指南

目标：让一个用户完成第一次网页聊天或 API 调用，而不仅是能登录后台。此流程基于当前源码；远程环境准备与发布见[部署步骤](deployment.md)。本轮修复已覆盖聊天、限流和渠道选择器；浏览器与真实发布验收仍待完成，见[验证状态](known-issues.md)。

## 配置顺序

### 1. 先确认环境和管理员

- 核对 Worker 版本、`DB` / `CACHE` / `GATE` 绑定、`PUBLIC_BASE_URL` 和可信 HTTPS
- 应用目标环境全部未应用迁移；源码目前为 `0001`–`0023`
- 新环境只通过[初始管理员脚本](admin-bootstrap.md)创建第一个管理员；没有默认账户/密码，不要用该脚本重置已有账户
- 管理员初始余额也为零，注册策略不会因为初始化而自动开放

### 2. 配置公开模型和价格

打开 `/admin/models`，核对要提供给用户的公开模型是否启用、价格是否符合自己的计费规则、最大输出和准入门槛是否合理。

`0018` 提供 23 个内置模型参考项，但不创建渠道映射或用户授权。目录中的供应商名称、价格和上下文信息只是记录时的参考，不能证明当前上游账户已开通对应模型，也不会自动同步供应商涨价。后续迁移 `0019` 已移除默认输出配置，不能依赖网关替客户端补输出限制。

### 3. 创建分组与渠道

1. 在 `/admin/groups` 核对启用的分组与计费倍率；不同组可以提供不同渠道和费用倍率
2. 在 `/admin/channels` 创建渠道，配置实际 Base URL 和上游 API Key，关联需要的分组
3. 配置渠道的状态、优先级、并发和每分钟限制；有限 RPM 仅接受 1–4096 的安全整数，0/空值沿用不限语义。“不限”不代表 Cloudflare 或供应商没有限制
4. 通过“配置模型”添加公开模型 → 上游模型的映射，核对实际上游协议 `chat` / `responses` / `messages`
5. 按实际能力配置 streaming、stream usage、工具等特性，不能为让页面出现模型而声明供应商不支持的能力

分组与模型映射编辑器会读取完整渠道分页，全部成功后才可保存；读取失败可重试，已有绑定和停用项继续回显。渠道主列表仍按页展示。

网页聊天只展示具备 `streaming` 的映射；`chat` 上游还需要 `stream_usage`。所以 API 模型列表可见、但网页聊天不可见，可能是能力条件不同，不一定是用户授权丢失。更细的模型映射编辑可在模型管理中进行。

### 4. 给用户授权并授额

在 `/admin/users` 创建或选择用户，核对账户启用状态、默认组和允许访问的分组，按需要设置限额并授予余额。

- 用户可以获准访问多个组，但每个普通平台 API Key 绑定一个选定组
- 新用户和公开注册用户余额默认零；有账户、有分组、有 Key 都不代表能开始调用
- 注册码只用于注册资格，不能替代余额授额
- 余额调整应填写可追溯的原因；结果不确定时先查账单，避免重复授额

### 5. 验证一条完整链路

先让测试用户确认可见模型、Key 分组和余额，再执行经批准的最小模型调用，最后查看用户请求记录、管理员请求、账单与审计。

渠道“测试连接”会向真实上游发请求，可能消耗供应商额度；它不扣用户余额，也不能证明用户授权、网页聊天、端到端结算全部正常。真实调用测试要先明确测试账户、模型和费用预算。

### 6. 最后开放注册

在 `/admin/registration/settings` 设置关闭、开放或注册码注册。若开启邮箱验证，必须先配置真实发送能力，并完成实际投递检查。staging 仓库配置当前为 `EMAIL_VERIFICATION_READY: "false"`、`send_email: []`，不能直接视为邮件可用。

仅在理解后果后调整邮箱验证开关；不要把 `EMAIL_VERIFICATION_READY` 改成 true 来绕过发送故障。注册码在 `/admin/registration/codes` 管理，明文只在生成时显示。

## 没有可用模型时的检查顺序

按这条链路检查，通常比反复新建 Key 更有效：

1. 用户 active，且拥有目标分组授权，授权时间已经生效
2. 分组 active；网页聊天选对组，API Key 绑定的组正确且 Key 未过期/撤销
3. 公开模型 active
4. 至少一个 active 渠道关联该组
5. 该渠道有对应公开模型映射，上游模型名/协议正确
6. 网页聊天额外满足 streaming；`chat` 上游满足 stream_usage
7. 开始调用前余额为正且满足模型准入门槛，限额/并发和上游凭证可用

`GET /v1/models` 使用平台 Key 权限，网页聊天模型目录使用登录用户可访问组和流式能力。二者不是同一份无条件全站模型列表。

已存的超上限 RPM 值不会自动修正，运行时仍拒绝执行；应另行审核并纠正配置。4096 是配置上限，不是已验证容量，长 operation ID 会占用 Gate 的 64 KiB 状态预算。

## 日常运维入口

| 页面 | 用途 |
| --- | --- |
| `/admin/requests` | 请求状态、来源、模型、失败与结算问题 |
| `/admin/billing` | 账单和余额相关检查 |
| `/admin/audit` | 管理操作追踪 |
| `/admin/users` | 用户状态、分组授权、额度和限额 |
| `/admin/channels` | 渠道状态、模型映射与显式连接测试 |

看到 `usage_unknown`、待结算或恢复记录时，先核对原始请求和已知用量，不手工伪造零费用。Cron 和恢复机制有边界，详情见[部署](deployment.md)、[计费](billing-cache.md)和[备份恢复](backup-restore.md)。
