# 前端重设计

已发布至 [staging](https://sub2api-cloudflare-staging.alphazhang689.workers.dev)，版本 `3028d2ff-8427-4e7c-aa34-1d5fcac401dc`。

## 视觉与信息组织

使用暖白纸色、墨色文字、朱砂强调色和细分隔线，以排版与信息层次组织页面。使用原生 CSS 变量、系统字体和内联 SVG，没有新增 Tailwind、UI 组件库、远程字体或图片依赖。

- 公开首页以协议连接图解释 Chat / Responses / Messages 的关系；登录与注册使用左右分栏。
- 已登录界面改为固定分组侧栏、当前位置和主工作区；手机使用可收起导航。
- 账户页突出实时余额、可复制的完整接口地址和最近五条真实请求。没有图表占位或虚构统计，未知费用保持“待确认”。
- 管理表格统一密度、边线与操作层级。删除重复的页面说明、可由表单自行表达的权限/版本说明，以及重复的金额最小单位展示；管理员用户列表改为准确的 USD 展示。
- 操作错误、发送结果不确定、密钥一次性显示和金额输入单位仍保留。模型能力列表收进可展开区域。
- 分组和渠道诊断使用原生模态弹窗；余额长数字在手机上调整字号，保留完整精度。

## 验证

- Vue TypeScript 检查与前端构建通过。
- API client 单元测试 8/8；原有注册、管理、完整协议计费浏览器流程 9/9。
- 最后的模态改动另跑管理浏览器流程 1/1。
- 本地 12 组桌面/手机视觉检查，无页面横向溢出；另验证复制完整接口地址、模态背景不可聚焦、Escape 关闭和手机最大余额显示。
- 发布后，真实 HTTPS 上的 11 项检查通过：新首页资产、既有管理员登录与余额、六个业务页面、移动导航、退出、手机首页。账号与原有配置保留，注册仍关闭。

旧管理测试依赖表格中显示的渠道 UUID 和最小金额单位，已改为从真实管理 API 获取渠道 ID，并断言页面中的准确 USD 金额；原有业务与账单断言保留。

本轮没有修改数据库迁移、计费后端或上游配置，也没有调用真实模型或发送邮件。测试使用的模拟渠道与大额余额只存在本地隔离环境。
