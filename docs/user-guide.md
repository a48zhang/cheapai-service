# 用户上手指南

本文说明本轮实现后的操作流程。2026-10-03 的修复尚未发布，浏览器验收受阻；你访问的站点可能运行旧版本，使用前请管理员确认部署版本与[验证状态](known-issues.md)。

## 1. 登录前准备

向站点管理员确认：站点 HTTPS 地址、注册方式、可用模型/分组，以及余额如何授予。

- **关闭注册**：已有账户仍可登录，新用户由管理员处理
- **开放注册**：填写邮箱和密码
- **注册码注册**：还需要一枚有效注册码；注册码不提供余额
- **邮箱验证**：若站点开启，先获取验证码再提交；重发会使旧码失效。未收到时先检查邮箱和冷却提示，再联系管理员确认邮件服务

密码当前要求 6–128 个 Unicode 字符且最多 512 UTF-8 字节，建议使用独立强密码。当前没有自助找回密码入口，忘记密码请联系管理员。注册成功会创建零余额账户；若注册已成功但登录会话建立失败，先直接登录，不要反复消耗注册码。

## 2. 最快开始：网页聊天

1. 登录后打开首页 `/`
2. 在模型选择器中选择管理员开放的分组和模型；分组名称旁的 `×` 是计费倍率
3. 输入一条短消息并发送，回答会逐步显示
4. 历史会话可继续、改名或删除；侧栏有更多历史时点击“加载更多”，加载失败可保留已有列表并重试
5. 生成时可停止，最后一轮回答可重新生成并切换版本
6. 到“请求记录”与“账单”核对使用情况

网页聊天使用当前登录身份，不需要先创建 API Key，与 API 调用共用余额。重新生成是新的模型调用，可能产生新费用；停止生成也不代表已发生的上游用量免费。

会话过期后会回到登录页；同一账户登录后可恢复本地未发送草稿。主动退出或更换账户会清理或隔离旧草稿，浏览器存储不可用时无法保证恢复。

当前页面提供文字输入，不提供附件上传。网关的条件图片输入支持不能等同于网页聊天已支持上传图片。离开页面、刷新或断开连接不提供后台继续生成/流式续传保证；先查看会话和请求状态，再决定是否重试。

遇到“暂无可用模型”时，用户无法自行添加模型或上游密钥，需要管理员检查[配置链路](admin-guide.md#没有可用模型时的检查顺序)。遇到“余额不足”时先申请授额。

## 3. 在自己的客户端使用 API

### 创建并保存平台 Key

1. 打开“API Key”页 `/keys`，选择“创建 API Key”
2. 填写名称、选择一个已授权分组，按需设置到期时间
3. 保存本次显示的完整密钥；关闭后无法再次读取明文

如果密钥丢失，应撤销旧 Key 后新建。创建结果不确定时用页面的“重试确认”，不要刷新后连续创建。平台 Key 用来调用本站，不是上游供应商 Key；不要把它放在 URL、截图、公开仓库或客服对话中。

### 配置地址与模型

- API Base URL 通常填写 `https://你的站点/v1`；有些客户端自行追加 `/v1`，需按客户端约定避免 `/v1/v1`
- API Key 填写刚保存的平台 Key
- 模型 ID 使用当前 Key 可见的公开模型名，不使用管理员的私有上游别名
- Chat Completions、Responses、Messages 对应三个不同的接口路径，具体能力见[协议支持矩阵](protocol-support.md)

先查询模型，不会调用上游生成：

```sh
# 把占位值替换为站点地址；密钥由你自己的安全配置方式注入环境变量
export SUB2API_BASE_URL='https://your-site.example/v1'
# SUB2API_API_KEY 应已在当前终端安全设置，不要把真实值写进本文件
curl --fail-with-body "$SUB2API_BASE_URL/models" \
  -H "Authorization: Bearer $SUB2API_API_KEY"
```

成功返回 `object: "list"` 和 `data` 数组。合法 Key 也可能得到空数组，表示目前没有对它开放的模型；不是安装客户端就能解决的问题。

选取返回的一个模型 ID，发起第一次短调用。以下请求会消耗上游用量和站点余额：

```sh
curl --fail-with-body "$SUB2API_BASE_URL/chat/completions" \
  -H "Authorization: Bearer $SUB2API_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"替换为可见模型ID","messages":[{"role":"user","content":"你好，请用一句话回复。"}]}'
```

需要流式输出时加入 `"stream":true`，并给 curl 加 `-N`。不要假定所有供应商支持完全相同的参数；如需限制输出，按当前模型和协议设置受支持的输出上限。网关不会自动补充默认输出上限，Messages 等要求该字段的路径必须满足其协议与渠道约束。

这两条命令使用 Bearer 鉴权。网关也识别 `x-api-key`；避免同时发送内容不同的两套鉴权头。浏览器登录 Cookie 不能替代 `/v1` 的平台 Key。

## 4. 余额、请求与账单

- 新账户从零余额开始，当前通过管理员授额/调整余额使用；没有自助支付充值流程
- 余额在调用前决定是否准入，实际费用在调用后结算；正在执行的并发请求可能使余额短暂为负
- 网页聊天记录的请求来源是“网页聊天”，普通客户端是 API 请求；请求详情可协助追踪模型、状态、用量和费用
- 连接报错不一定意味着上游没有执行。出现未知用量或待结算时，先查请求状态，不要把它当成免费成功或立即重复调用

## 5. 常见卡点

| 现象 | 建议下一步 |
| --- | --- |
| 登录后仍无法发送 | 检查余额和可用模型；向管理员提供时间、页面与请求编号 |
| 回答一开始显示就报格式错误，或重新生成后变回旧答案 | 本轮已修复相关正文/操作收尾路径；先核对线上版本和请求状态，不要连续生成来排查，以免产生多次费用 |
| 会话过期后无法重新登录 | 本轮已接入受保护请求 401 的会话失效与安全回跳；若仍异常，请记录版本与步骤，手动复制草稿后再刷新 |
| 注册被关闭或缺少注册码 | 联系管理员确认注册方式，注册码不等于充值码 |
| 收不到验证码 | 检查邮箱、重发冷却和最新验证码；由管理员确认真实邮件已启用并验证 |
| API 返回 401 | 核对平台 Key 是否完整、到期、撤销；不要使用浏览器 Cookie 或供应商 Key |
| 余额不足 / 402 | 申请授额，并确认当前分组倍率及模型准入门槛 |
| 403 或“暂无可用模型” | 核对 Key 绑定分组、用户分组授权、模型/渠道启用与映射；交给管理员排查 |
| 参数不支持 / 400 | 对照协议与渠道能力，保留必要语义，不盲目删除参数掩盖兼容问题 |
| 429 | 降低请求频率/并发并检查重试提示；持续发生请管理员查用户和渠道限制 |
| 503 / 服务暂不可用 | 保留请求编号交管理员查配置、路由、D1/DO 或上游；不要连续自动重试有费用的请求 |
| Key 创建结果未确认 | 保留当前页面，使用同一操作的“重试确认”；若已创建但明文未收到，撤销后重新创建 |

对外反馈只需脱敏的报错、发生时间、请求编号和操作步骤。不要发送完整 Key、密码、验证码或敏感聊天内容。
