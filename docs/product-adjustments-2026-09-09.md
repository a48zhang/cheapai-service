# 六项产品调整

已发布至 [staging](https://sub2api-cloudflare-staging.alphazhang689.workers.dev)，版本 `b1ee855e-980f-4a91-a125-bc49dd25fc96`。

1. 密码最少六个字符，注册、管理员创建用户和 bootstrap 一致。最大字符/字节约束与 Argon2id 参数不变，既有密码继续可用。
2. 用户、渠道并发支持不限，新建默认不限；界面留空、API 传 0/null 均可表达不限。既有明确配置保留。内部以安全整数最大值兼容既有正整数存储和租约接口，不设额外业务数值上限；RPM 为独立设置。
3. 渠道列表展示已配置的上游模型，渠道内可新增/编辑模型映射。诊断从该渠道的模型选项获取版本，不再要求手填版本号。这是配置的模型信息，不宣称已自动探测供应商实际能力。
4. 管理员通过“默认分组 / 开放分组”给用户授权，可开放多个分组。每个 Key 选择一个已授权分组；可用模型由该组关联的渠道和模型决定。所有鉴权、模型列表、余额准入、最终请求登记都以 Key 的组重新核对授权，撤权或禁用组立即阻止新访问。Key 可切换到其他已授权组，凭据不变。
5. 首页移除协议路由图和协议互转介绍；账户页移除协议入口面板，保留余额、请求和账户操作。
6. Key、用户、渠道、模型、邀请码和余额弹窗整理同级操作按钮；筛选栏、复选框与表格单元格对齐。去掉重复 URL 预览和无助于操作的版本说明，必要单位与不可逆操作提示保留。

## 数据兼容

`0017_key_groups.sql` 在现有用户的默认组上建立初始授权，给现有 Key 绑定默认组，并将旧的空模型限制转为组权限；旧的非空模型子集保留兼容，重新保存分组时清除该旧限制。没有重新生成 Key、修改密码或更改余额。该迁移已通过标准远程 D1 migrations apply。

默认组必须位于用户开放分组内。管理员授权只在原有权限校验、CAS 和审计的同一事务中更新；用户不能自行开放分组。原有会话账户状态检查及最后管理员保护继续执行。
