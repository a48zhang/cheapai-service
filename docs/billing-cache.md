# 计费与 KV

## 准入与结算

用户先充值或由管理员授额。新请求直接读取 D1，要求余额大于零，并检查用户、Key、分组和模型权限。数据库读取失败时拒绝准入。

调用前登记请求及价格快照，结束后从原始上游 usage 计算实际费用。已发生的消费完整入账，因此并发请求可能使余额变负；在途请求继续执行，余额非正时拒绝新请求。高成本或长时间请求可能增加透支金额。

金额使用定点整数：1 USD = 100,000,000 units。API 输出十进制字符串；互斥 Token 计费桶汇总后按 half-up 取整到一个 unit。

账单插入、余额增减和请求状态更新在同一 D1 原子操作中完成。重复结算键比对原 fingerprint，匹配时返回已有结果，冲突时拒绝。消费账单只追加，人工纠错使用独立 adjustment。管理员授额同样使用唯一操作 ID 和账单明细。

客户端重新生成回答是新的调用；同一内部请求的结算重试沿用原结算标识。

## KV 缓存

D1 保存用户、权限、余额和账单。KV 缓存路由候选、模型映射、价格和可选余额快照；发送前仍以 D1 核对权限及余额。

路由和价格缓存携带配置版本，每个请求固定价格快照。余额缓存初始关闭；启用时携带 `balance_units`、`observed_at` 和 `schema_version`，过期则回源。时间戳取 D1 读取开始时间，回填和重试保持原值。

KV 跨地区更新与删除可能延迟。同键写入限额、429 或回填失败按缓存失败处理，继续使用 D1 结果。缓存回填不能覆盖 D1；账单、扣款和一次性凭证消费均在 D1 执行。

## 失败处理

| 情况 | 处理 |
| --- | --- |
| 账单已提交，响应丢失 | 按相同请求标识查询或重试结算 |
| 已收到 usage，D1 暂时失败 | 有限重试；usage 已持久化时由 Cron 幂等补结 |
| Worker 终止，usage 未持久化 | 保留请求并标记待核对 |
| 上游缺失最终 usage | 标记未知用量，人工调整保留审计 |

未知用量不按零费结算。维护任务的批量、重试次数和退避见[部署手册](deployment.md#7-发布后验证和维护)。
