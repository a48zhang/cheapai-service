# 并发与 RPM 默认不限

用户在明确区分并发和每分钟请求数后，授权“不设置这个限流”。已发布版本 `7f75a6d1-7395-43f0-866f-77911006085a`。

- 新用户、新渠道的并发和 RPM 都默认不限，界面留空或 API 的 0/null 表示不限。
- 网关在不限 RPM 时不提交每分钟窗口限制，继续管理请求租约、结算与取消。
- 用户表格分为“并发请求数”和“每分钟请求数”，避免原“并发 / RPM”混合展示。
- 先前已将两个旧账户的默认并发 2 清除；本次经明确授权，将三个账户、一个渠道的旧 RPM 60 改为不限。通过管理员接口及 CAS 更新，保留其他配置和审计；没有修改余额、状态、组授权或上游密钥。
- 停用账户即使所属组已停用，也可调整限额；不会激活账户或组。实际返回的 group_status 保持正确。

验证：类型检查、相关单元/原生 D1-DO 回归和两项浏览器闭环通过。专门测试在同一分钟持有 65 个请求，确认并发超过 2、请求数超过 60 时仍可准入，随后全部释放。公网核对更新后的字段、独立表头与手机编辑表单通过，详见 [公网结果](evidence/unlimited-limits.json)。本轮未调用真实模型上游。
